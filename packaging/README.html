Fortnite Visual Chest Counter

Automatically count Fortnite chests from gameplay video · v0.2.3 public beta · Windows 10 / 11 · no Python or programming needed

What this is

A small app for players and streamers. It recognises the chest-opening pop-ups in Fortnite gameplay video and keeps a running count of the chests opened — from a Twitch or YouTube livestream link, anything shown on a screen, your own stream's OBS feed (one PC or two), a capture card or a recorded video. If you want the numbers on stream, it writes them into a text file that a normal OBS text source shows (you choose the font, size and colours in OBS). Chest counting uses gameplay video. Optional match automation and mode detection read Fortnite's local log. See fair play and compatibility.

CERTAIN

Confirmed openings.

APPROX

Additional estimated openings.

TOTAL

The sum of Certain and Approx.
The OBS text and CLI use the legacy APPROX total, which includes confirmed openings.

This is a public beta. APPROX is an estimate, not a perfect count. In our recorded test streams it matched the real number closely, but computer vision is never 100%. See Known limitations.

Count from a Twitch or YouTube livestream URL

No OBS, capture card or browser needed. In the app: Video source → Livestream URL (Twitch / YouTube), paste the link (https://www.twitch.tv/CHANNEL or a YouTube watch?v= / @CHANNEL/live link), keep Stream stability: Maximum stability (recommended), click Start counting. The stream must be live and public. Tested for hours at a time (a 3-hour session counted about 500 chests).

  • The counter reads the stream as viewers get it, a few seconds to about a minute behind, and checks every picture in order. Delay does not matter for the count.
  • Stream stability: Maximum stability = lowest buffering risk, most delay (best for long sessions); Balanced = moderate buffering risk; Low latency = higher buffering risk, not recommended when complete counts matter. No setting can bring back video the platform never delivered.
  • Good to know: video can arrive in bursts or pause to buffer; ad breaks and stream restarts can make the counter miss chests. The app reconnects by itself, keeps your counts, and says so clearly (red Reconnecting in the status, the Activity log and over the Live preview), including how many seconds could not be seen.

Count what is on a screen

Play the stream, video or game fullscreen on one of your monitors, pick that Screen in the Video source list (it shows each screen’s size; Refresh after plugging one in) and click Start counting. Turn on Live preview once to check that the counter sees the game with its HUD.

  • The gameplay must fill the screen. A small player inside a web page (with chat and menus around it) is too small to read — nothing is counted. Use the player’s fullscreen button.
  • Keep other windows off that screen while counting. A 16:9 screen works best.

What you need

  • Windows 10 or 11.
  • Fortnite shown in a 16:9 picture (1920×1080 is ideal; 1280×720 or higher works) with the HUD visible, in English, Brazilian Portuguese, or French.
  • About half of one CPU core. No graphics card needed.
  • OBS Studio 28 or newer only if you count from your own OBS scene, or want the numbers on stream.
  • Nothing else to install. Everything the app needs is already inside the folder.

Your own stream with OBS: the 30-second version

  1. Unzip the folder anywhere you can write files (Desktop or Documents is fine).
  2. In OBS: make a scene called ChestDetectorFeed with only your game in it, and start the Virtual Camera from that scene.
  3. Open Fortnite Visual Chest Counter.exe, pick OBS Virtual Camera as the video source and click Start counting.
  4. In OBS, add a Text source that reads obs_output\chest_counter.txt. The app’s Overlay page shows the exact path (with a Copy button) and lets you choose what it says.

Details for each step are below.

Your own stream: single-PC setup (game and OBS on the same PC)

1. Unzip

Right-click the zip → Extract All. Do not run it from inside the zip, and don’t put it in Program Files. The folder contains:

Fortnite Visual Chest Counter.exe   <- the app: the only thing you open
README.html                    this guide
config.example.toml            optional advanced settings (see "Settings")
obs_output\                    the text files OBS reads
state\  logs\                  your counter and logs (kept when you update)
runtime\                       program files (the official Python runtime from python.org, FFmpeg, Qt) - don't touch

2. Make a clean feed for the counter in OBS

The counter must see only the game picture (no webcam, alerts or overlays covering the screen). The easiest way is a separate scene that you never show on stream.

  1. Open OBS. In the Scenes box click + and name the scene exactly ChestDetectorFeed.
  2. In the Sources box click + → Game Capture → OK. Set Mode to “Capture specific window” and choose Fortnite (start Fortnite first so it appears in the list). If Game Capture shows a black picture, use Display Capture instead.
  3. Make Fortnite fill the whole scene: select the source and press Ctrl+F (“Fit to screen”).
  4. Do not add a webcam, alerts, chat or the chest-counter text to this scene.

3. Start the Virtual Camera from that scene

  1. In OBS, find the Controls box (bottom-right). Click the small gear next to Start Virtual Camera.
  2. Set Output Type to Scene and Output Selection to ChestDetectorFeed. Close the window.
  3. Click Start Virtual Camera. It now shows as running.

Your normal stream scene is unaffected: viewers still see whatever scene you choose. The counter reads only ChestDetectorFeed.

4. Start counting

Open Fortnite Visual Chest Counter.exe. On the Dashboard, pick OBS Virtual Camera as the Video source; click Start counting. The status at the top right changes to Counting, and a line under the video source shows the picture size and how many pictures per second are analysed (about 15).

Leave the app open while you play; you can minimise it. Each chest appears in the Activity panel the moment it is counted and the big numbers go up. To stop, click Stop counting (or close the app; it asks first). Your numbers are saved after every chest and are kept for next time.

If a red message says “OBS Virtual Camera was not found”, follow the steps it shows (open OBS, Start Virtual Camera, click Start counting again).

5. Show the numbers on stream

See Show it on stream below.

Two-PC setup (gaming PC + streaming PC with a capture card)

Gaming PC / console ↓ HDMI Capture card ↓ Streaming PC → OBS → scene "ChestDetectorFeed" → Virtual Camera → Fortnite Visual Chest Counter
  • Unzip and open the app on the streaming PC (the one running OBS). Nothing needs to run or be installed on the gaming PC or console.
  • In OBS on the streaming PC, create the ChestDetectorFeed scene and add your capture card as a Video Capture Device source. Make it fill the scene (Ctrl+F). Nothing else goes in this scene.
  • Set the Virtual Camera to Scene → ChestDetectorFeed and click Start Virtual Camera (exact clicks in step 3 above).
  • In the app, pick OBS Virtual Camera as the video source and click Start counting — the same as on one PC.
Advanced: reading the capture card directly (no Virtual Camera). Your capture card also appears in the app’s Video source list (“Capture device: …”). Many capture cards can only be opened by one program at a time, so this does not work while OBS is using the card. If the app says the device cannot be opened, switch back to OBS Virtual Camera.

Other video inputs (Virtual Camera already in use?)

For OBS users whose Virtual Camera is already taken, or who want to read a capture card directly. These are marked less tested in the Video source list (click Refresh if you just plugged something in):

Turn on Live preview on the Dashboard to check that the counter sees the game, full screen, with the HUD.

Show it on stream (OBS text source)

The counter only writes the text. You style it in OBS however you like. You need one source:

  1. Open the scene your viewers see (not ChestDetectorFeed).
  2. In Sources click + → Text (GDI+) → name it “Chests” → OK.
  3. Tick Read from file, click Browse and choose obs_output\chest_counter.txt (inside the counter folder). The app’s Overlay page shows this exact path; Copy path puts it on the clipboard.
  4. Choose a font, size and colour. Click OK and place it on screen.
Put the text source only in the scene your viewers see, never in ChestDetectorFeed.

Customize what viewers see

Open the Overlay page in the app:

  • What OBS shows: both numbers on two lines, both on one line, only the estimated total, or only the confirmed chests. Each choice shows an example with your current numbers.
  • Wording: put # where the number goes, e.g. Chests opened: # or Chest Hunt: #/500. For the one-line choice, #C is the confirmed number and #A the estimated total. Original wording brings the default text back.
  • Preview shows exactly what the text file will contain. Click Apply: OBS updates at once, even while counting.

OBS always reads the same file (chest_counter.txt), whatever you choose, so you never change the OBS source. Any text, symbols and emoji work (emoji need an OBS font that has them).

The app cannot hide a Text source you already added in OBS. If you see a number you did not choose, that source reads a different file: point it at obs_output\chest_counter.txt or hide it. The app’s Dashboard always shows both numbers — that is for you, not for viewers.

Advanced: the same settings live in config.toml under [display]. For separately styled sources, the counter also writes:

File (in obs_output)Contains
chest_counter.txtThe one to use: whatever you chose on the Overlay page (all four layouts).
chest_status.txtLegacy: one line with both numbers (or the single number you chose).
certain_chests.txtAlways the confirmed number.

Activity panel and live preview (optional)

Both are on the Dashboard and are only for you — showing, hiding or minimising them never changes what is counted.

Activity lists what the counter sees and decides, live: green = certain chest · yellow = counted in APPROX only · red = looked like a chest pop-up but was not counted. match 0.94 is how closely the pop-up word matched (0–1), not a percentage or probability. Switch Normal detail to Debug detail to also see every candidate, the full reason for each decision and a status line every few seconds.

Live preview shows the picture the counter is analysing (a few times per second), so you can check that it sees the game full screen with the HUD. It is off by default and costs nothing while hidden.

Everything is also written to the session log in logs\, whether the panels are open or not.

Help improve accuracy: marks and diagnostic recording (optional)

On the Dashboard, Diagnostic recording (off by default) keeps the video the counter analysed, so a missed chest can be replayed and checked later. Change it any time, also while counting — the counts are not affected:

  • Only around my marks — the smallest: the counter keeps a short rolling recording and saves only the 30 seconds before and 10 seconds after each mark.
  • Around chest decisions and my marks — also about 20 seconds around every chest the counter considered.
  • Whole session — large (about 10 GB per hour), for finding chests the counter never noticed.

Mark a missed chest: right after the counter misses a chest (or counts something that was not one), press Ctrl+Alt+M — it works while Fortnite has the focus — or click Mark moment. A green “Marked” line confirms it. Marking needs a recording running (there is no video to keep otherwise), so the button is grey and the hotkey only shows a hint while recording is off. Lossless (Settings) keeps exactly what the counter saw, so a replay reproduces every decision, at about twice the disk space.

Each counting session gets a folder in captures\ with the video, every decision the counter made and a labels.csv you can fill in (chest, not_chest, missed_chest…). Review captures… on the Settings page replays every capture through the current version of the counter and compares it with what was counted live and with your labels; it shows which capture it is on, how much video is done and, once the speed is known, the time left. Recording never slows down or changes the counting; it needs at least 2 GB of free disk space and stops by itself below 1 GB.

Counting a recorded video

The app can also analyse a prerecorded gameplay video (.mp4, .mkv, .mov…). On the Dashboard click Analyse a recording…, choose the file and click Start. It runs faster than real time, shows progress and each counted chest, and finishes with the CERTAIN and APPROX numbers (APPROX includes CERTAIN). This never changes your live counter; the result text files go to video_output\. The video should be clean 16:9 gameplay with the HUD visible, in English, Brazilian Portuguese, or French.

Already opened chests? Set a starting count

On the Dashboard click Edit. Enter any chests opened before starting under Approx and leave confirmed openings at 0. Total is the sum of confirmed and estimated openings. The OBS text and CLI use the legacy APPROX figure, which includes confirmed openings.

Profiles: separate counts per person

Count several streamers (or yourself and others) without mixing their numbers: the Profile row on the Dashboard has New profile…, Rename… and Delete…. Each profile keeps its own counts, its own chest-type split and its own video source (for example that streamer’s Twitch link). One profile counts at a time; switch when counting is stopped. OBS always shows the selected profile, so the OBS text source never changes. Counts from earlier versions are the Default profile. A deleted profile’s counts are kept as a backup in state\profiles\deleted\.

Chest types

The chest-type breakdown splits the total by what the pop-up says: Chest, Rare chest, Sprite chest, or Unknown type when the line could not be read reliably (a chest is never guessed to be a normal one). It is a label only: CERTAIN and APPROX are counted exactly as before, and OBS still shows only the totals. Chests counted before v0.2.2, or set with Edit counts…, are listed as not classified. Chest types are read for English and French pop-ups.

Reset the counter (e.g. at the start of a stream)

On the Dashboard click Reset… and confirm. Both numbers (and the chest-type split) of the selected profile go to 0, also while counting. Closing and reopening the app does not reset anything; your totals continue.

Matches, Group and Discord

Choose Auto in the Dashboard mode selector to read the playlist from Fortnite's local log, or choose a mode manually. The Pirate Token multiplier is manual. Use Finish match to save to the local history. With Settings → Match automation enabled, Battle Royale warmup starts a fresh count and the lobby return saves it.

In Group, save a player name and the shared webhook on each PC. Enable Share matches with my group to submit results. The Host configures and starts the bot, publishes one leaderboard and shares the message ID with Guests. A Guest can read the last published settings even when the bot is offline.

The bot needs View Channel and Read Message History in the webhook channel and Message Content Intent in the Developer Portal. Add Send Messages and Embed Links for reports. Use /chests and /leaderboard in the server. /add and /reset require Manage Server.

Settings (optional)

By default the app starts in the Windows system tray. Open it from its tray icon. The default capture is Screen 1 with HDR-to-SDR conversion and English HUD recognition at 15 analysed frames per second. Match automation and Auto mode are enabled. Group sharing is off.

Most people never need to change anything. The Settings page has the Fortnite language (English, Portuguese (Brazil), Both, or French; pick the one your game is set to), the session logs and the optional diagnostic recording. Changes are used the next time you click Start counting. Remember window size and position (on by default) reopens the app the way you closed it, maximised or not; a window whose monitor is gone is moved back onto a screen.

Advanced: everything else is in config.toml (Settings → Open config.toml; every option is explained inside). A mistake in the file only produces a warning and the default is used for that option.

Updating to a new version

From v0.2.3 on, the app has a built-in updater (experimental). Shortly after opening it checks for a new version and, if there is one, shows a small Update available link in the sidebar. Choose Download & Install: counting keeps running while the update is downloaded and prepared, and Restart & Install finishes it. It is built to keep your counts, profiles, settings and OBS sources, and to return to the previous version by itself if a new one does not start properly. Nothing is downloaded or installed unless you choose to. The automatic check and the download speed are in Settings > Updates.

The updater has not installed a real update yet: v0.2.4 will be the first. If it does not work, update by hand with the steps below, which work for any version. Moving to v0.2.3 from an older version also needs these steps, because older versions have no updater.

Your counter, settings and logs are stored next to the program files, never inside them:

KeepWhat it is
state\Your saved counts (every profile).
config.tomlYour settings (if any were changed).
logs\Session logs (optional to keep).
obs_output\The text files OBS reads (they are re-created automatically).

Easiest update: close the app, then extract the new zip into the same folder and choose “Replace the files”. The zip never contains your counts or config.toml, so they are untouched. Opening the app afterwards writes your real numbers back into the OBS text files (the zip contains blank placeholders). If you extract to a new folder instead, copy state\ and config.toml across, and re-point the OBS text source to the new obs_output folder.

Coming from v0.1.x: after extracting, delete the old .bat and .cmd files from the folder — v0.2.0 is one app, Fortnite Visual Chest Counter.exe. Your counts, settings and OBS sources keep working.

Fortnite compatibility

The chest detection in v0.2.2 recognises English chest pop-ups on a normal, larger or smaller HUD, chests added to a pop-up already on screen (“RARE CHEST X2”, another chest line), and Brazilian Portuguese pop-ups on a normal HUD. It was developed and live-tested during Fortnite Chapter 7 Season 5 (November 2026); its automated tests also use recordings of earlier gameplay and real-world cases from user recordings. It recognises Fortnite’s on-screen chest pop-up and HUD elements, which Epic Games can change in any update. If chests stop being counted after a Fortnite update, please report it on the project’s GitHub page (Issues: https://github.com/GabrielGzS/fortnite-visual-chest-counter/issues) with the diagnostics report.

Known limitations (please read)

  • APPROX is an estimate. It can be a little high or low. CERTAIN is the conservative number; APPROX is the best guess of the total.
  • Language: chest detection uses the word in the pop-up. Supported: English (CHEST), Brazilian Portuguese (BAÚ), and French (COFFRE). Chest types are read for English only.
  • HUD layout: it expects the HUD in its usual place at a 16:9 picture. For English pop-ups a HUD drawn larger (up to about 1.3×) or smaller (about 0.8×, tested on one stream) is recognised; those chests count in APPROX only, never CERTAIN. Other HUD sizes, a moved or hidden HUD, Portuguese pop-ups on a non-standard HUD, or a 4:3 / vertical picture will not work well.
  • Chests opened in quick succession are added to the pop-up on screen (“RARE CHEST X2”, “X3”, another chest line). They are counted (multiplier steps in APPROX only); two chests within a fraction of a second can count as one — never as two for one chest.
  • Livestream URL sees what viewers get: bursts, buffering, ad breaks and reconnects. Video the platform never delivered cannot be counted. Screen: the gameplay must fill the screen.
  • Clean gameplay feed recommended: overlays, webcam or alerts on top of the HUD can hide the clues.
  • Audio is not used. Only the picture is analysed.
  • Tested on a limited number of recordings (PC English, PS5 Portuguese, streams with a larger and a smaller HUD, 11 labelled real-world cases) and live sessions up to several hours. Physical capture cards and real OBS projectors are not tested yet. Other platforms or settings may behave differently — that’s why this is a beta.

Fair play and compatibility

The counter is built for statistics and stream presentation: it counts chest openings that are already visible on screen. It gives no competitive information — it does not locate hidden chests, reveal enemies, aim, move or play for you. Chest detection reads video frames. Optional match features read the local Fortnite log. Ctrl+Alt+M marks a missed chest using a Windows hotkey.

Epic Games’ rules prohibit tools that use real-time gameplay information to gain a competitive advantage. This app is designed for counting, not for competitive assistance — but Epic does not certify individual third-party applications, and this one has not been reviewed or approved by Epic. The most conservative ways to use it: count recorded video (Analyse a recording), or run the counter on a separate streaming PC (two-PC setup), so nothing from this project runs where Fortnite runs. Running it on the same PC as Fortnite works technically; in one developer session the app analysed a livestream on the same PC while Fortnite was being played, and BattlEye did not interrupt the game — one observation, not a guarantee. Its compatibility with Fortnite’s anti-cheat has not been officially verified, and anti-cheat behaviour can change at any time. A two-PC setup is not a compliance guarantee either; it simply keeps the counter away from the game. Tournament or event rules can be stricter — check them if you compete.

Privacy and safety

Network features include livestream capture, update checks and optional Discord sharing. Diagnostics are saved locally when enabled. Group sharing sends match statistics to the configured Discord webhook.
